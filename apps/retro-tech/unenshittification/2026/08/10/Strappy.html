Imagine a World

Imagine a world, an alternate universe perhaps, where Apple made different decisions. A world where the “OS X iPhone” (Source) was really an OS X iPhone. A world without sandboxing. A world without required signature checks. A world where trust was established between the user and the developer, not Apple.

In this world, iPhone apps are as powerful as Mac OS X apps. In this world, users have access to their own data from any app they trust. In this world, users can build and run their own software on their own device. In this world, apps on the device can write, compile, install, and run new apps on the same device. In this world, the iPhone is a “Bicycle for the Mind” just like the Mac. In this world, the iPhone is as useful as the Mac, not just an overpowered device for “casino games for children” (source), toxic social media doomscrolling, and simple chat apps.

What is Strappy

Strappy is my personal strap-on AI harness. Strappy has a big, sassy, and very gay personality… I mean, Strappy’s physical embodiment is a 12” strap-on rainbow “tool,” let’s say. But like most gays, Strappy is insanely diligent, detail-oriented, and strict… like dominatrix-strict.

But in all seriousness, Strappy is more like a proof of concept or an art project (and maybe also a little bit of a “fuck you” to the tech establishment). Strappy is meant to make people think about what the world I explained above could have been like. What would the world be like if Apple did not artificially restrict the capability of their our devices? I hate reminding people that every Mac ever sold has come “Jailbroken,” but it’s true. I am not sure why Apple is so adamant that every other device they sell aside from Macs needs to have all of its power and usefulness stripped out of it due to restrictive policy decisions.

What Can Strappy Do

Strappy is like Siri AI for Retro Apple Devices. Strappy includes a suite of tools that the LLM can use to query your data from your apps on your iPhone. They also include a coding assistant. Yes, a coding assistant! So that you can vibe-code iPhone apps RIGHT ON YOUR PHONE! It’s actually pretty incredible. And because Strappy is built on OpenRouter, you can select which models you use and restrict model providers by their training and data privacy policies.

Depending on the assistant type you choose, different tools are made available to the LLM. This way you can always control what Strappy is capable of in any given session. And actually, you can change them mid-session as well.

Personal Assistant

This is where things get exciting. This is “Siri AI for Retro Apple Devices.” One thing I noticed while working with AI coding tools on my Mac was that the LLM was insanely good at reading arbitrary data from raw SQLite databases. Because I happened to remember that SQLite had been the bundled and recommended database for iPhones since the original iPhoneOS 2 SDK (dubious reference), I thought, “What if I just found every database on the iPhone and then made it accessible to an LLM?” And that’s how it all started. Because Strappy is a “normal” (read as non-sandboxed) app, they can scan your entire home folder for SQLite databases used by all of your apps. Then I built some simple tools that allow the LLM to make read-only SQL queries against the databases. Lastly, I added in a whitelisting system so that you can control which databases the LLM can query. With this basic system in place, Strappy is able to make quick work of your databases and find all sorts of information in there to answer your questions. Yes, they can read your address book, calendar, email, messages, and even third-party apps which also generally use SQLite databases. It’s actually really quite impressive how well the LLM does at parsing and organizing your data.

Data Privacy and Safeguards

Strappy includes the following always-enabled protections for your databases:

  1. Databases are whitelisted, so only the databases you select are exposed to the LLM.
  2. The model only receives data from SQL queries, not the whole database. Results are limited to 100 rows per query to limit the size of network requests.
  3. Databases are opened using SQLITE_OPEN_READONLY. This is verified via a SQLite authorizer that rejects PRAGMA, writes, ATTACH, transactions, attached-database reads, and dangerous functions such as load_extension, readfile, writefile, and pragma_*.
    1. Any violation will cause the tool to return the following error to the LLM: “Error: database_query only permits one read-only SELECT or EXPLAIN query against the approved database. PRAGMA, ATTACH, writes, filesystem access helpers, and transaction statements are not allowed.”

But I want to be clear: your data is being sent to someone else’s servers without end-to-end encryption. Normal HTTPS/TLS protects it in transit between you and OpenRouter. After that, OpenRouter chooses the cheapest provider for that model and sends the data to that provider.

But OpenRouter includes extensive controls to limit WHO your data is sent to and what rules they are expected to follow via its “Guardrails” feature. So if you are worried, set up spending limits, whitelist models, whitelist providers, enable Enforce Zero Data Retention Policies, and configure regex-based prompt-injection detection.

Of course, if you wanted to run your own local LLM, there is no reason Strappy could not talk directly to your own local model. In that case, no data would leave your premises.

Coding Assistant

I have always been really inspired by the simplicity of the Pi.dev AI harness. It is famous for only having 4 simple tools: file_read, file_write, file_edit, and bash. With only these 4 tools, the LLM can do anything on your computer. So I found that Cydia (the jailbroken phone package manager) had packages to install very old versions of Clang and other basic compiler tools. So I took a risk and implemented those 4 basic tools in Strappy… and it worked! I was shocked. With only these 4 tools, Strappy was able to write and compile simple C programs with Clang. But getting Strappy to build full iPhone apps, well that was a bit tougher. But don’t worry, I persevered. I used Altivec Intelligence to build the Altivec Toolchain Debian package (yes, jailbroken iPhones use the Debian package manager) that includes Clang 15 and other much more modern tools like ld, ldid, otool, libtool, make, etc. I also built little scripts that manage which iPhoneOS SDK is downloaded and installed, plus a library manager that lets you download the custom Altivec libraries I use for all of my retro apps. Those libraries provide Font Awesome and other UI components, as well as modern libcurl, cJSON, and SQLite. But anyway, I am rambling.

The short answer is yes, Strappy can “one-shot” and “vibe-code” iPhone apps from your prompt. They can write them, compile them, analyze them, install them, and launch them for you. It’s really amazing to watch… even though it shouldn’t be… Because remember, in this world, computers have always had apps that can write, compile, install, and run other apps. It’s not a new concept at all. It’s just something Apple restricts us from doing on iPhones.

System and Data Integrity

The only safeguard is old-fashioned UNIX permissions. Strappy runs under your user account, which does not have root privileges, which protects system files from modification and deletion. But yes, Strappy can delete all of your files. And yes, one time Strappy did that! They ran rm -rf /var/mobile/Applications and deleted 40 applications from my iPhone before I noticed and stopped it. So tread lightly. But yeah, in this world without sandboxing, we do live in more peril. But somehow on the Mac we survive.

The 4 tools I provided in the coding assistant are extremely basic and totally un-sandboxed. If you know anything about the coding assistant tools, you know that most of their complexity comes in trying to sandbox the LLM. I follow Pi.dev’s philosophy; once you give the LLM a bash tool, it is not possible to sandbox. This is why Strappy ships with the bash tool turned off, even in Coding Assistant mode.

I thought about adding sandboxing to the file_read, file_edit, and file_write tools. This would be quite simple. But if the bash tool was enabled, the LLM could just bypass the sandboxed tools with bash…

I also thought about trying to create a new user on the system and then run bash as that user. That way, those bash sessions would only be a risk to data created by that user. But the ways to do this are not stable across major macOS and iOS versions, and so I put it off for now even though it would be highly effective. I might still try to do this in the future.

How Does Strappy Work

You may or may not know this, but the OpenAI so-called “Responses API” is actually a very simple JSON-based web API. Even though Codex or Claude might seem like super sophisticated applications, they are just JavaScript HTTP clients. Their core function is to send and receive JSON data over HTTPS just like any other application. And as I have said in 2026: The Year of Unenshittification, you don’t need an 8” supercomputer in your pocket to send, receive, and display JSON data… you just don’t.

Strappy is just that: a basic HTTP client that sends and receives JSON. They use libcurl, cJSON, and SQLite from my Altivec Intelligence package to get modern networking functionality. Strappy has a native interface for everything except the core Prompt Session view which is an HTML page rendered in C and then pushed to a web view via JavaScript one API round trip at a time. The most novel features are the tools which enable the LLM to operate efficiently.

System Requirements and Installation

Strappy is 99% vibe-coded and “100% compiled” (reference). Strappy is free and open source on GitHub under the MIT License. As I said above, there is nothing special about this app. Strappy is a JSON-parsing HTTP client, so please enjoy reading through a lot of boilerplate code for JSON parsing and database storage and retrieval.

https://github.com/jeffreybergier/Strappy-Cocoa

iOS

Supports iOS 4.3+ but has only been tested on iOS 6, 8, and 15.

  1. Jailbreak your phone
  2. Enable SSH login
  3. Download a release of Strappy
  4. Copy the .deb file to the iPhone and install it
  5. (Optional) Download and install Altivec Toolchain for the coding assistant
    1. Install it the same way you installed Strappy
scp ~/Downloads/Strappy-X.Y.Z-iOS.deb root@iphone-ip-address:~/strappy.deb
ssh root@iphone-ip-address "dpkg -i strappy.deb && rm strappy.deb"

Depending on how new the SSH client on your computer is and how old the OpenSSH server on your phone is, you may need to manually allow the use of older RSA encryption algorithms.

  scp -O \
    -o HostKeyAlgorithms=+ssh-rsa \
    -o PubkeyAcceptedAlgorithms=+ssh-rsa \
    ~/Downloads/Strappy-X.Y.Z-iOS.deb \
    root@iphone-ip-address:~/strappy.deb

  ssh \
    -o HostKeyAlgorithms=+ssh-rsa \
    -o PubkeyAcceptedAlgorithms=+ssh-rsa \
    root@iphone-ip-address \
    "dpkg -i ~/strappy.deb && rm strappy.deb"

Mac OS X

Supports Mac OS X Tiger 10.4+ as a quad-fat binary for PPC, i386, x86_64, and arm64, but has only been tested on 10.4 (PPC and Intel), 10.5 (PPC), 10.6 (Intel), 10.8 (Intel), 10.9 (Intel), 10.14 (Intel), and 15.0 (arm64).

  1. Download a release of Strappy
  2. Unzip and then run the app (as God intended it)

The Mac version of Strappy has the personal assistant feature, just like the iOS version. However, SQLite did not start to become a common standard for Mac apps until after the iPhone came out. So Strappy may not have access to much useful data. For example, Mail.app does not use a SQLite database on Mac OS X.

Caveats

  • Altivec Toolchain is currently only built for armv7 and iOS 6+.
  • The OpenRouter Web Tools are not reliable at all. To be fair, OpenRouter says that both the Responses API and the Web Tools are in beta as of this writing, so I am doubling up beta pain into a pretty unreliable experience.
  • Strappy only uses OpenRouter API-key-based pricing and is therefore pay-per-use. Most good models cost a lot more than you would want to spend. I want to add ChatGPT OAuth but have not done so. It is also unclear whether unofficial clients are allowed to do this.
    • As of this writing, I have had the best price-to-performance ratio with DeepSeek v4 Flash 731 and ChatGPT 5.6 Luna. However, I dislike how Luna and OpenAI models basically refuse to take on a gay personality.

What I Learned

LLMs Are Dumb

LLMs are dumb. Like really dumb. It is really hard to get them to follow instructions. You need to make every interaction with them and all guidance you give them as simple as possible or else they will mess up. Using bigger models helps, but they are still pretty dumb. Writing my own harness made me realize this. What feels like magic in Codex and Claude CLIs is apparently just a lot of work on the harness… because the models are DUMB. But I persevered and came up with the toolset above to try to work around the models’ shortcomings. I feel like it works “good enough.” But I wish I could force the model to do more without tying it up in knots.

As an example of this, though, I don’t want the model to use emoji because retro devices do not have good emoji support. So I included Font Awesome and basic Markdown syntax so the model could use Font Awesome. I eventually got the model to use Font Awesome reliably. But the model also has multiple reminders to NEVER EVER EVER use Unicode Emoji. It’s in the system prompt and several tool descriptions, etc., but sometimes the model STILL uses emoji!! It’s not the end of the world. But don’t expect the model to do anything you ask of it reliably.

Don’t Build Your Own Harness

For mostly the reasons I stated above and a few others, just don’t do this. There are soooo many edge cases you need to handle. For example, sometimes there is just no answer from the LLM. It’s just completely missing. Then it’s your choice as the harness developer: do you just let everything die there and leave the user hanging, or do you ask the model to keep going? How many times do you do that? Also, every model is different and has different random issues!

If you want to automate your own agent, just use Pi.dev. It’s super easy because it has already handled most of these cases. It also has a TypeScript library, so your TypeScript app can import it and use it like any other library. No installation needed.

I had to build my own harness because I needed it to be written in C, and no one has done that as far as I can tell. I do not recommend it.

The Harness is “Flexible”

The Responses API is based on a concept called “items.” Each request and response is just a list of items. Items include things like Thinking, Answer, Tool Call, Tool Response, Tool lists, Prompt with a role attribute, etc. The harness entirely controls how these items are managed and which ones are included in the “context.” This means you can put any item into a request, even if it came from a different model or session—or was completely made up. In fact, I found great success doing this as part of the user’s initial prompt. With each initial prompt, I artificially inject Tool Calls, Tool Responses, and an Agent Answer into the network request.

This was BY FAR the most effective technique I found for controlling what the model sees and does. Even more effective than controlling the system prompt. So you may have noticed this in the demo videos, but each session always starts with the same initial answer from Strappy and the same initial tool calls. That’s because my harness is hardcoded to inject the following Agent Answer even though the LLM never said anything like this:

  • World Knowledge: “Strappy here, babe. Facts, line up. Let me check my memories and tools before I put the world in order.”
  • Personal Assistant: “Strappy here, babe. Databases, behave. Let me inspect my memories, skills, and approved data before I interrogate the evidence.”
  • Coding Assistant: “Strappy here, babe. Code, heel. Let me inspect the environment, review my tools, and find out exactly what needs discipline.”
