## Outline

1. **Open With the Demo: Ask an Old Device a Personal Question**
   - Start with Strappy running on a retro Mac or jailbroken iPhone.
   - Ask something that a generic chatbot cannot know, but that can be answered
     from an approved local database.
   - Show Strappy identify the relevant database, inspect its saved context,
     run a bounded read-only query, and turn the result into a useful answer.
   - Establish the central idea: an assistant becomes personal when it can help
     me use data I already own.
   - Add a short screen recording or a sequence of screenshots from the actual
     device used for the demo.

1. **What Is Strappy?**
   - A native OpenRouter-powered AI assistant for old and new Apple devices.
   - The Mac app targets Mac OS X 10.4 Tiger and later in a four-architecture
     universal binary: PowerPC, 32-bit Intel, 64-bit Intel, and Apple silicon.
   - The iOS app targets iOS 4.3 and later with armv7 and arm64 slices and is
     installed as a `.deb` on jailbroken devices.
   - Clarify that the language model runs remotely. Strappy is the native
     client, conversation system, and controlled bridge to the device; it is
     not an on-device LLM.
   - Link back to the Altivec Intelligence and ENIL posts as the foundation for
     making modern networked software run on retro Apple platforms.

1. **Why I Built It**
   - Modern AI clients increasingly require modern operating systems, even
     though sending text to an API is an ordinary computing task.
   - Generic assistants can search the web, but they know almost nothing about
     my actual life.
   - Contacts, calendars, email, messages, and many other apps already keep my
     information in SQLite databases on my own devices.
   - I wanted to choose the hardware, model, and data involved instead of
     accepting one vendor's vertically integrated assistant.
   - Connect this goal to the Unenshittification Manifesto: my data should be
     usable by software I choose, on devices I choose.

1. **One App, Three Assistants**
   - **World Knowledge** handles general questions, remembered facts, and
     optional web research without access to personal databases.
   - **Personal Assistant** is the default and adds controlled access to
     approved local databases.
   - **Coding Assistant** can inspect and edit text files and, only when
     explicitly enabled, run Bash commands in a selected working directory.
   - Explain that these are real capability boundaries, not cosmetic personas:
     each assistant receives a different tool set, preflight context, quality
     policy, and separate memory.
   - Mention Database Study as a fourth, internal workflow rather than a
     user-facing chat mode.

1. **Turning Local Databases Into Personal Context**
   - Strappy scans the selected part of the filesystem for actual SQLite
     databases instead of trusting filename extensions.
   - It catalogs valid databases, associates them with their likely apps and
     locations, and shows them in native Preferences screens.
   - Nothing becomes available to the assistant merely because it was found:
     I must explicitly approve each database.
   - The Personal Assistant gets three deliberately narrow database tools:
     list approved databases, load context for one database, and run a bounded
     read-only SQL query.
   - Queries reject writes and enforce time, row, column, and result-size
     limits.
   - Database schemas and private rows are fetched only when a question needs
     them instead of dumping the contents of my device into every prompt.
   - Add two or three real examples, such as finding a contact, summarizing a
     message history, or answering a calendar question, based on databases that
     work well on the demonstration device.

1. **Database Study: Teaching Strappy How My Apps Store Data**
   - SQLite is common, but every app invents its own tables, relationships,
     timestamp formats, and naming conventions.
   - Strappy's internal Database Study workflow inspects an approved database,
     discovers useful user-data entry points, and tests exact retrieval
     recipes.
   - It saves a short description and reusable, evidence-backed query context
     rather than copying schemas or sampled private values into memory.
   - Later Personal Assistant sessions can find the right database and query
     it more accurately without rediscovering everything from scratch.
   - The study results are visible in Preferences and can be reset and rebuilt
     by the user.
   - Show the database approval and Database Study screens side by side.

1. **Bring Your Own Model**
   - Strappy fetches the OpenRouter model catalog and stores model metadata
     locally.
   - Preferences provide searchable and sortable model browsing, including
     context limits and input/output pricing.
   - I choose which models are allowed, set a default for new chats, and select
     a different allowed model for an individual session.
   - Web access is also a choice: None, Auto, Native, Exa, or Parallel, with
     web fetch available when a page needs closer inspection.
   - On the Mac, the OpenRouter endpoint and token can be stored in Keychain.
   - Frame this as practical freedom: the app belongs to me, and the
     intelligence provider remains replaceable.

1. **A Coding Assistant on Retro Hardware**
   - Coding Assistant can read bounded ranges of UTF-8 files, create or
     overwrite files, and apply exact text edits.
   - Bash access begins disabled, is enabled per session, runs each command in
     a fresh non-interactive shell, and has a hard timeout.
   - Each coding session has a selected working directory, so filesystem tools
     and shell commands operate in the same place.
   - A first-prompt environment probe tells the model what system, filesystem,
     SDKs, headers, and developer tools are actually available.
   - Consider a recursive demo in which Strappy inspects or makes a small
     change to its own source code on a retro device.
   - Emphasize that command execution is extra authority and therefore stays
     opt-in.

1. **Showing Its Work**
   - Conversations and their selected model, assistant, settings, requests,
     responses, tool calls, tool results, errors, usage, and costs persist in
     Strappy's own SQLite database.
   - The native app uses a WebView timeline to show reasoning, tool activity,
     retries, errors, and answer-quality reports instead of hiding everything
     behind a spinner.
   - Old rounds can be included in or excluded from future model context with
     a checkbox, giving the user direct control over what the next prompt sees.
   - Requests can be cancelled, and tool failures remain visible in the
     conversation.
   - Mention the playful Font Awesome-powered personality and activity labels:
     a personal app does not need to inherit a corporation's voice.

1. **The Agent Has House Rules**
   - Strappy assembles a different system prompt from the tools and goals of
     the selected assistant instead of sending one enormous universal prompt.
   - First-prompt preflight calls provide fresh memory, database availability,
     or coding-environment context as appropriate.
   - Every final answer gets a visible quality report. Checks include a
     non-empty answer, references after web research, appropriate database
     context, session naming, and Strappy's Font Awesome convention.
   - The report informs me when the answer missed a rule; it does not silently
     spend more tokens asking the model to repair itself.
   - Explain why this matters on paid APIs: correctness checks and token use
     should be inspectable behavior.

1. **How Modern AI Runs on Tiger and iOS 4**
   - The shared engine is portable C built around libcurl, cJSON, and SQLite;
     the native AppKit and UIKit interfaces are Objective-C.
   - The OpenRouter Responses API client, tool loop, filesystem scanner,
     database layer, prompt builder, quality checks, and WebView renderer are
     shared by both apps.
   - SQLite is the source of truth for UI-visible conversation state. Provider
     JSON is parsed at the network boundary and stored as normalized semantic
     records rather than saved as opaque request and response blobs.
   - HTML, CSS, and JavaScript for the chat timeline are generated by the C
     renderer so old WebViews receive one consistent interface.
   - Small XP compatibility layers bridge newer Cocoa behavior at runtime while
     preserving the oldest supported SDK calls.
   - Altivec Intelligence supplies the cross-compilers and modern networking
     libraries that make the same source build for decades of Apple hardware.
   - Add a simple architecture diagram: OpenRouter on one side, Strappy's
     shared C core in the middle, and native Mac/iOS UI plus approved SQLite
     databases on the device side.

1. **What “Local” and “Private” Actually Mean**
   - Filesystem scanning, database cataloging, SQL validation, and queries
     happen on the device.
   - The assistant can access only databases I approve, and its SQL access is
     read-only and bounded.
   - Relevant query results still have to be sent through OpenRouter to the
     selected remote model. Strappy is not an offline or fully local AI system.
   - Using personal databases therefore requires trusting the selected model
     provider with the specific context needed to answer a question.
   - Coding Assistant's optional Bash access is more powerful than database
     access and should be enabled only when appropriate.
   - The jailbroken iOS build is intentionally unsandboxed so it can find app
     databases; that power is the point, but it also deserves explicit care.

1. **Caveats and Current Status**
   - Strappy is a version `0.1` personal project and still needs release
     hardening and broader real-device testing across its full OS and
     architecture matrix.
   - It requires internet access, an OpenRouter account and API token, and
     incurs the selected model's usage costs.
   - Database support is necessarily uneven. Some Apple databases use private
     SQLite extensions or unusual schemas that ordinary read-only SQLite
     cannot fully reproduce.
   - Strappy does not write to personal databases, replace the apps that own
     them, or make unsupported devices secure merely by running on them.
   - iOS installation requires a jailbroken device and `.deb` package.
   - Add download, source, and support links only after deciding what is ready
     to distribute for the August post.

1. **Why Strappy Is Unenshittification**
   - It makes old hardware useful instead of treating a simple text interface
     as a reason to buy a new device.
   - It makes existing personal data useful without waiting for every app
     vendor and platform owner to grant a new integration.
   - It lets me choose the model, approve the data, inspect the tool activity,
     and control conversation context.
   - It is intentionally personal, opinionated software built around my goals
     rather than a funnel into somebody else's ecosystem.
   - End on the larger point: I did not need a new phone to get a modern AI
     assistant. I needed a better bridge between modern models, old computers,
     and data that was already mine.
