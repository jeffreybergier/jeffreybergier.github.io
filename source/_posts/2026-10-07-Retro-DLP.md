## Back to YouTube

At the end of my [Strappy AI post]({% post_url 2026-08-10-Strappy %}), I
mentioned that I could have spent that time making something practical like a
YouTube app. Well, here we are.

My iPhone 5 can play videos. My PowerPC Macs can play videos. Getting those
videos from YouTube is the annoying part. So in my ongoing effort to
[unenshittify my life]({% post_url 2026-02-22-Unenshittification-101 %}),
I made Retro-DLP.

## What is Retro-DLP

Retro-DLP is a small reimplementation of part of yt-dlp in C, with native apps
for iOS 5+ and Mac OS X Tiger+. Give it a video or a playlist, download it,
and watch it. You can also sync playlists from your account.

That's the experience I want. Pick something to watch and watch it on a
device I like. The downloaded videos are ordinary MP4 files. On the Mac,
playback uses VLC. On iOS, I made a player with playlist support.

There is also a command-line tool and a C library, so the native apps aren't
the only way to use it.

## Why Is Downloading YouTube Videos So Hard

You might think downloading a video means finding a URL and downloading it.
And yes, eventually. But first there is JavaScript homework.

YouTube's web player doesn't reliably hand you a ready-to-use video URL.
Parts of the URL need to be transformed by functions buried in the player's
JavaScript. YouTube supplies both the puzzle and the code to solve it, but
you still need a working modern JavaScript engine to run that code. Good luck
asking the Safari that came with Tiger to do that.

So even when the device can play the video, getting a usable download URL
can be the thing that stops you. Apparently downloading an MP4 requires
bringing part of a modern browser along for the ride.

## How Does It Work

Thankfully, QuickJS is a modern JavaScript engine written in C that can run
on these old devices. Retro-DLP uses it to run yt-dlp's EJS solver, which
finds the relevant logic in YouTube's player and uses it to finish the video
URLs. All of this happens on the device, without running a whole web browser.

Modern networking comes from libcurl and OpenSSL, using the
[Altivec Intelligence]({% post_url 2026-04-22-Altivec-Intelligence %}) toolchain.

Sometimes the audio and video arrive separately. L-SMASH combines them into
one MP4 without re-encoding. This matters because asking a PowerPC Mac to
download a video is one thing. Asking it to convert the whole video before
I can watch it is another.

The core libraries are C, with EJS supplying the JavaScript solver. The apps
wrap this in UIKit and AppKit.
Old devices, native interfaces, modern networking. You know the drill by now.

## The Annoying Parts

This does not magically make an iMac G4 good at decoding HD H.264. I already
wrote about that in my [Retro Stream Tutorial]({% post_url 2025-08-17-Retro-Stream-Tutorial %}).
You still have to choose a quality your device can play.

And solving the JavaScript challenges does not solve every YouTube restriction.
Retro-DLP doesn't generate Proof of Origin tokens, so higher-quality downloads
can fail. The README covers this, cookies, and the other limitations.
