## YouTube on Retro Apple Devices

There are so many challenges with playing back YouTube videos on retro Apple
devices. I covered this in detail in my 
[Retro Stream Tutorial]({% post_url 2025-08-17-Retro-Stream-Tutorial %}) so 
I won't go through everything here, but the short story is:

- H.264 video codex is very difficult to decode on retro devices without dedicated hardware
- The [TLS apocalypse](https://en.wikipedia.org/wiki/Software_rot#Online_connectivity) means that retro operating systems likely can't connect at all
- YouTube uses sophisticated JavaScript to verify a real browser is being used to view videos

[yt-dlp](https://github.com/yt-dlp/yt-dlp) is a well-known open source project 
that attempts to solve at least the last problem. On modern systems it uses 
something big and heavy like the V8 JavaScript engine to pretend to be a 
browser. But yt-dlp can be paired with lightweight JavaScript engines like 
QuickJS as well. The problem with yt-dlp on retro systems is that its written in 
Python and so even if it could run (and yes, occasional retro builds do show 
up), its incredibly slow because... Python.

## What is Retro-DLP

Retro-DLP is a minimal reimplementation of of yt-dlp written in C, with a 
library, a CLI, native apps for iOS 5+ and Mac OS X Tiger+. I did my best to 
match the CLI arguments of yt-dlp in the hopes that if you are already 
familiar with yt-dlp, you will also be familiar with Retro-DLP.

Why did I choose yt-dlp as the base? Well, I like this tool, I like the way
it works, and I like the options it gives you:

- Use with or without YouTube authentication
- Select the audio and video formats you want with fallbacks if unavailable
- Muxes the audio and video together into a playable movie file
- Parses private and public playlists

So basically, I sat down with the AI and made a plan on how to port this in a 
way that works with Retro systems. Keep in mind that to build PowerPC Mac apps,
we need projects written in C99 or older so they can compile with Apple GCC 
4.2.1. Here is the basic plan we came up with:

- [AltivecIntelligence]({% post_url 2026-04-22-Altivec-Intelligence %}) provides AltivecCore with [libcurl](https://curl.se/libcurl/), [openssl](https://www.openssl.org/), [sqlite](https://www.sqlite.org/)
   - This is my in-house Docker container for developing retro apps
   - These provide all the basic networking and storage primitives we would 
     need
- [L-SMASH](https://github.com/l-smash/l-smash) to mux the audio and video files together
- [QuickJS](https://bellard.org/quickjs/) for the JavaScript engine
- yt-dlp ["EJS" Solver](https://github.com/yt-dlp/ejs) JavScript to solve the challenges 
- A custom C library to contain the core functionality
- A custom C CLI application to make the yt-dlp matching CLI
- Cocoa and Cocoa Touch apps to polish it off and make it easy to use

## How Retro-DLP Works

As with all of these projects, I stand on the shoulders of giants. And in this
case, its a super giant because QuickJS is written by 
[Fabrice Bellard](https://bellard.org/). Fabrice Bellard also wrote 
[FFMPEG](https://ffmpeg.org) and [QEMU](https://www.qemu.org/) which 
are the foundational technologies the web is built on. They are all written in 
C and provide incredibly sophisticated functionality with incredible efficiency.

Retro-DLP follows the same path as yt-dlp to download videos:

1. Connect to Youtube and fetch the Player Javascript (libcurl + OpenSSL)
1. Fetch special [EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS) Solver JavaScript (libcurl + OpenSSL + yt-dlp)
1. Solve the JavaScript challenges presented by YouTube (QuickJS)
1. Fetch the Audio and Video files from Youtube (libcurl + OpenSSL)
1. Mux together the Audio and Video files into a single MP4 (L-SMASH)

This is my favorite kind of integration project. Take well known, battle tested
C libraries and bundle them all together to solve problems in a unique way.
The fact that this can run on a PowerPC Mac running Mac OS X Tiger from 2004
is mindblowing. And of course if you have a fast internet connection, the 
slowest part of the operation is the JavaScript part, not the downloading part, 
because... JavaScript

## How I Use Retro-DLP

### Longform Content

I like to watch a bit of a YouTube video while I eat lunch. Sounds boring, but 
my work life is generally meetings so its how I take a break from so many 
conversations. On my iPhone 5 I use 
[Reeder](https://www.macstories.net/reviews/reeder-2-review-2/) with 
[RSS-THE-PLANET]({% post_url 2026-03-22-RSS-THE-PLANET %}). This service 
proxies feeds behind TLS 1.2, as well it does some work to shrink big images, 
reduce the size of the RSS file by trimming history, etc. What does this have to 
do with YouTube? Well RSS-THE-PLANET also has a little feature I made where it 
acts as an official YouTube API-using application. It can fetch my YouTube 
subscriptions as well as those account's newest videos using the official YouTube 
API and then convert them into an RSS feed. This Subscriptions RSS feed then 
appears in Reeder where I can copy and paste the URL into Retro-DLP and then 
download and watch the video. Its a great system and much nicer than trying to 
navigate the YouTube website. Eventually I will add the Subscriptions and Videos 
for Accounts working Retro-DLP, but for now, RSS-THE-PLANET is working fine.

Retro-DLP also supports syncing YouTube playlists which is the other way 
I get long format content into Retro-DLP. If I see a video on YouTube that I
want to watch later, I add it to a playlist of my choosing and then it will
appear for download in Retro-DLP.

### K-POP Stan (Shortform Content)

I love K-POP and around December 2025 as I was preparing for the
[year of unenshittification]({% post_url 2026-02-22-Unenshittification-101 %}), 
I got iTunes on my iMac G4 to sync with my 
[iPhone 5]({% post_url 2026-02-16-Reverse-iTunes-1 %}) (which is officially 
unsupported) and then I started bulk buying used CD's from my favorite groups 
and ripping them 1by1 into iTunes like it was 2003. It was sooo awesome! This 
synced music in the Music app on my iPhone 5 represents the bulk of my music 
listening. However, K-POP moves fast! New songs and videos are being released 
all the time. So I have a playlist in YouTube to keep track of these before I 
buy the CD and import them into my iMac G4. Since Retro-DLP has playlist 
support, it is very easy for me to make sure these are always downloaded on my 
iPhone 5 and ready for listening or viewing. Since Retro-DLP supports playback 
with or without video as well as in the foreground or the background, it has 
become a de-facto music player for me as well.

## Custom Video Player

On Mac OS X, Retro-DLP does not have a video player. Its a Mac app and is 
therefore its allowed to interact with other Mac apps (novel, I know). With
this basic computing super-power that was taken from us on the iPhone, Retro-DLP 
maintains playlist files that are compatible with 
[VLC](https://www.videolan.org/vlc/). This means that any playlist in Retro-DLP
can be opened in VLC and it "Just Works" because its a Mac.

Of course on iOS, its not so easy. I made the decision to make Retro-DLP
a normal sandboxed iOS app distributed as an IPA even though I knew it would
mean I could not play the video in VLC which is what I really wanted. But
its just so much easier for people to install IPA's... hell, even iTunes
will do it for you. So I went down that path. But that meant I needed to build
a custom video player in iOS which is something I never wanted to do because
they are actually fiendishly complex with a lot of implicit behavior that you
might not know is there.

I spent a lot of time making the custom video player in the iOS app really 
nice and I tried to hide the complexity so hopefully no one would notice 
how much functionality it has built in. What complexity you ask? 

- Background and foreground playback (both in app and out of app)
- Playback with and without video
- Lock screen and control center support
- Playlist support
- [Video gravity](https://developer.apple.com/documentation/avfoundation/avlayervideogravity) toggle support
- Longform and shortform video playback
   - Previous/Next buttons behave differently
   - Previous/Next buttons have different icons
   - Playback position saved for longform video
- Coming Soon
   - Display brightness control with swipe up and down
   - Audio delay control with swipe left and right
   
Yeah, it does a lot but it still only has like 4 buttons and a slider. I am 
happy with how well I was able to hide the complexity. And before you 
ask, no I did not use 
[`AVPlayerViewController`](https://developer.apple.com/documentation/avkit/avplayerviewcontroller) 
because that was introduced in iOS 8 and I support iOS 5+.

## Known Problems

### No PO Token Support

YouTube keeps making it harder to download videos outside of a browser (for 
obvious reasons). One of the major ways they do this is called a PO token. This 
technique is a tougher JavaScript challenge that requires DOM interaction. At 
this point (2026/11), aside from the lowest quality 360p (18), videos basically 
require a PO Token to download. Currently it seems like if you have a YouTube
premium subscription, then the PO token is also not always required.

See the [yt-dlp PO Token Guide](https://github.com/yt-dlp/yt-dlp/wiki/Po-Token-Guide) for more info.

Retro-DLP will never generate a PO Token because QuickJS does not support DOM 
API's. If a PO Token becomes required, I will need to find a different strategy 
for YouTube downloads.

### H.264 Only

YouTube now supports newer codecs, but Retro-DLP is H.264 only. And this is 
because Retro Computers can barely handle H.264, let alone something newer. 

Also, Retro-DLP does not fix the issue that your PowerPC Mac will probably 
barely be able to play the 360p (18) or 
[480p (135+142)]((https://gist.github.com/sidneys/7095afe4da4ae58694d128b1034e01e2)) 
quality videos without dropping a lot of frames. Maybe if you have a Dual CPU 
PowerMac G5, you will be able to play 720p (136+142)? But H.264 is just a tough 
format which is why it usually gets dedicated encoding and decoding hardware on 
modern devices.

If you want to see a solution for this that does not involve H.264 and uses
easier codecs like XVid, then check out my 
[Retro Stream Tutorial]({% post_url 2025-08-17-Retro-Stream-Tutorial %})

## Appendix

### Existing Solutions

I should call out that for iPhones, there there is 
[TubeRepair](https://www.reddit.com/r/LegacyJailbreak/comments/1oggj03/ios_6_youtube_fix_tutorial/) 
which keeps the original Apple YouTube app alive. This solution involves someone
hosting a server that replicates the REST API that the Apple app originally
relied on and proxying connections from that app to this custom server. It works
OK but its iPhone only and its not super reliable as its a hobby project. Plus
it does not work offline because it has the original limitations of the old app.
Also, you can't or definitely should not login because that would pass your
Google credentials to an unknown person. So no playlists or recommendations.
